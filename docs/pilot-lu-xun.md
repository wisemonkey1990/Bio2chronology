# 试点报告：鲁迅（1881–1936）

目的：用一位真实人物走完“取材 → 转换 → 评测 → 校订 → 上线”的全流程，检验抽取质量、校订成本和版权边界。

## 1. 取材与版权

| 来源 | 内容 | 许可 | 年龄写法 |
|---|---|---|---|
| Wikisource《俄文譯本〈阿Ｑ正傳〉序及著者自敘傳略》（1925） | 鲁迅自述生平，863 字，繁体 | 公有领域（作者逝世于 1936 年） | 虚岁 |
| 中文维基百科“鲁迅”条目·生平章节 | 7556 字，简繁混排 | CC BY-SA 4.0 | 周岁 |

- 两份文本均可合法使用和展示引文，已提交在 `people/lu-xun/source/`。维基百科内容按 CC BY-SA 4.0 要求在网站人物页署名、给出原文链接，并声明年谱中来自维基百科的部分按同一许可授权。
- 一般的出版传记受版权保护，**不应提交全文，网站展示的引文也要控制长度**。这是收录在世作者著作前必须先定下来的规则（见第 6 节）。
- 维基百科的 MediaWiki API 对匿名请求限流严重（HTTP 429），`fetch` 改为只用 `action=raw`，每页一次请求，并带上标识性的 User-Agent。

## 2. 评测方法

`people/lu-xun/eval/gold.json` 列出 25 个公认的生平节点（依据通行的鲁迅年谱），每个节点配若干特征词。

- **召回**：抽取结果中有事件摘要含特征词。
- **年份正确**：匹配到的事件里至少有一条年份正确。
- 只衡量关键节点，不衡量精确率（垃圾条目的比例）。精确率由第 4 节的人工预审统计。

运行：`python -m bio2chronology eval people/lu-xun`

## 3. 结果

同一套评测关键词下，规则引擎改进前后（未校订）：

| 来源 | 抽取条目 | 召回 | 年份正确 | 找到者中年份正确 |
|---|---|---|---|---|
| 自叙传略·改进前 | 3 | 16% | 8% | 50% |
| 自叙传略·改进后 | 17 | 44% | 32% | 73% |
| 维基百科·改进前 | 78 | 92% | 68% | 74% |
| 维基百科·改进后 | 122 | 92% | 84% | 91% |
| 两份合并·改进前 | 81 | 92% | 72% | 78% |
| **两份合并·改进后** | 139 | **92%** | **92%** | **100%** |

漏掉的两个节点（《呐喊》出版、周海婴出生）在这两篇文本里根本没有写，属于来源问题，不是抽取问题。

> ⚠️ **数字偏乐观**：规则修正是对着这两篇文本做的，评测集也是同一人编的，存在过拟合。必须再用一位**没参与调试**的人物验证，才能知道真实水平。

## 4. 校订成本（精确率）

改进后共抽出 139 条，逐条预审后：

| 处理 | 条数 | 典型情况 |
|---|---|---|
| 剔除 | 39（28%） | 丧仪流程细节 18 条；评论、回忆性引文、时评；背景说明；作者写作时的“现状”被误当作当年的事 |
| 合并 | 9 组 | 两份来源对同一事件的记述（出生、入水师学堂、回国、首用笔名……） |
| 修正年份 | 9 | 无时间词、沿用上文年份的句子（如在自述里“进了仙台医专”被归到 1898 年） |
| 修正分类或摘要 | 6 | “袁世凯病亡”被归入“疾病”；来源把三年的三份职务压在一句话里 |
| 仅加校注 | 1 | 一句话里写了 1898 年和 1902 年两件事 |
| 保持不动 | 75 | — |

**近一半（64/139）的条目需要人工处理**，最终上线 91 条。按这个比例，一部 20 万字的传记大约要处理上千条，必须有比编辑 JSON 更高效的校订界面。

本轮预审由 Claude 完成，所有决定都记在 `people/lu-xun/review.json` 里并附理由。保留的条目仍是“自动”状态，网站上显示为未经人工校订，**需要人工逐条确认**。

## 5. 试点暴露并已修复的问题

| 问题 | 例子 | 修复 |
|---|---|---|
| 不认繁体 | “十八歲”“三年後” | 新增繁转简字表（逐字对应，原文位置不变），只用于匹配，原文保持原样 |
| 虚岁与周岁 | 自述“十八歲”是 1898 年（1881+18−1） | 每份来源单独配置 `age_reckoning`；周岁结合生月判断是否跨年 |
| 年号 | “清光緒七年”“光绪19年” | 支持乾隆至宣统、民国 |
| “第N年” | “第二年……第三年” | 以同一个基准年计数，而不是逐年累加 |
| 括号里的年份 | “（1838—1904年）”“（1912年改制……）” | 时间识别跳过括号内容 |
| 把他人年龄当成传主年龄 | “时年28岁的朱安”“年仅七岁的儿子” | “N岁的X”中 X 不是传主时忽略 |
| 年龄覆盖明确年份 | “1918年，36岁的周树人……”被定在 1917 年 | 明确年份优先于相对时间，相对时间优先于年龄 |
| 自述里多数句子没有时间词 | “我于是進了仙台醫學專門學校” | 有事件特征的句子沿用上文年份，标记为“推断” |
| 出生前的背景被继承年份 | 祖父 1871 年中进士之后的“童年”描述 | 不继承早于生年的年份 |
| 同年内排序混乱 | 无月份条目排在有月份的之前 | 记录上下文月份，仅用于排序 |
| 重新转换会丢掉校订 | — | 校订改存 `review.json`，按条目指纹套用；新增“合并”操作；旧版内嵌校订自动迁移 |

## 6. 结论与建议

1. **年份推理基本可用。** 机器给出的年份在关键节点上已经比较可靠，主要误差来自来源本身的压缩写法，只能靠校订解决。
2. **瓶颈在精确率和校订效率，不在年份。** 下一步应优先做网页校订界面（原文与条目对照，一键剔除、合并、改年份），并在抽取阶段过滤评论和引文类句子。
3. **规则引擎的天花板已经可见。** 自述类文本里大量事件没有时间词，人物指代全靠上下文。建议用 LLM 引擎（`--engine llm`，需要 `ANTHROPIC_API_KEY`）在同一套评测上对比一次。本次试点环境没有 API key，未能测试。
4. **用第二位人物验证。** 选一位风格不同的人物（如以年号纪年为主的清代人物，或周岁写法的当代人物），不再调整规则，直接测，以评估过拟合程度。
5. **先定版权规则，再收录在版传记。** 包括引文长度上限、来源许可字段是否必填、哪些文本不提交到仓库。
